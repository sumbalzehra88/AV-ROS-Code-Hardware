# heading_controller_pkg

ROS 2 (Humble) C++ package containing 10 autonomous-vehicle control and
perception nodes — heading/PID steering, GPS-derived speed/distance,
accelerator control, steering alignment, checkpoint sequencing, and
Stanley path tracking — each with a unit-tested, header-only logic core
and a corresponding Google Test suite.

---

## Package Layout

```
heading_controller_pkg/
├── include/heading_controller_pkg/   # header-only *_utils.hpp per node (pure logic, no ROS deps)
├── src/                               # node .cpp files (ROS glue: topics, timers, params)
├── test/                              # gtest suites, one per node
├── python_files/                      # original Python versions of each node (for latency comparison)
├── CMakeLists.txt
├── package.xml
├── latency_test.py                    # C++ vs Python latency/jitter comparison harness
├── latency_comparison.xlsx            # generated by latency_test.py
├── latency_results.json               # generated by latency_test.py (source of truth)
└── README.md
```

## Nodes

| Node (executable) | Source file | Purpose | Key topic(s) |
|---|---|---|---|
| `heading_controller` | `src/speed.cpp` | PID heading/steering controller; loads CSV waypoints | `/steering_angle` |
| `gps_distance_velocity_node` | `src/speed2.cpp` | GPS distance travelled + speed (km/h, m/s) | `/speed`, `/speed_mps` |
| `gps_speed_controller` | `src/speed_controller.cpp` | Servo "foot-tap" accelerator, no alert | `/pwm_a` |
| `gps_speed_controller_alert` | `src/speed_controller_alert.cpp` | Same, + GNSS-checkpoint alert override | `/pwm_a` |
| `steering_monitor` | `src/dynamic.cpp` | Detects full lock-to-lock rebound sweep | `/point` |
| `gnss_heading_node` | `src/ahrs_sim.cpp` | GPS-only bearing + Kalman/EMA smoothing | `jmoab/ahrs` |
| `gnss_checkpoint_monitor` | `src/gnss_checkpoint_monitor.cpp` | YAML/CSV checkpoint sequencing + alignment request | `/point`, `/aligned` |
| `steering_aligner` | `src/dynamic_steering_aligner.cpp` | Adaptive-gain heading aligner, oscillation detection | `/steering_angle` |
| `stanley_controller` | `src/stanley5.cpp` | Stanley path-tracking control law | `/steering_angle`, `/control/command/control_cmd` |
| `steering_aligner2` | `src/steering_aligner2.cpp` | Simpler proportional aligner (no adaptive gain) | `/steering_angle` |

> ⚠️ `steering_aligner` and `steering_aligner2` share the same internal ROS
> node name (`steering_aligner`). Do not run both simultaneously without
> remapping one: `--ros-args -r __node:=steering_aligner2`.

## Prerequisites

- ROS 2 Humble
- `libyaml-cpp-dev` (used by `gnss_checkpoint_monitor` for YAML parsing — not a ROS package):
  ```bash
  sudo apt update && sudo apt install libyaml-cpp-dev
  ```
- `ros-humble-ackermann-msgs` (used by `stanley_controller`; the original
  `autoware_auto_control_msgs` dependency was unavailable via apt and was
  replaced with the standard `AckermannDriveStamped` message):
  ```bash
  sudo apt install ros-humble-ackermann-msgs
  ```
- `openpyxl` (only needed for the latency comparison tooling):
  ```bash
  pip install openpyxl --break-system-packages
  ```

Install any remaining ROS dependencies automatically:
```bash
rosdep install --from-paths src --ignore-src -r -y
```

## Build

```bash
cd /ros2_ws
source /opt/ros/humble/setup.bash
colcon build --packages-select heading_controller_pkg
source install/setup.bash
```

Re-run `colcon build` after any source change, then re-`source install/setup.bash` — `ros2 run` will not see new executables or picked-up code changes otherwise.

## Latency Comparison (C++ vs Python)

`latency_test.py` drives both the compiled C++ executable and the original
Python node (from `python_files/`) for each of the 10 nodes over real ROS 2
topics, measuring either **round-trip latency** (event-driven nodes) or
**publish jitter** (timer-driven nodes), and writes the comparison to an
Excel workbook.

### One-time setup
Paths in `PY_SCRIPT_PATHS` (top of the script) are already filled in to
point at `python_files/`. If you rename or move any Python file, update the
corresponding entry.

### List available nodes
```bash
python3 latency_test.py --list
```

### Measure one node at a time (recommended)
Each run measures both languages for that node and merges the result into
the same output files — safe to run in any order, any number of times:
```bash
cd /ros2_ws/src/heading_controller_pkg
python3 latency_test.py --node heading_controller
python3 latency_test.py --node gps_distance_velocity_node
python3 latency_test.py --node gps_speed_controller
python3 latency_test.py --node gps_speed_controller_alert
python3 latency_test.py --node steering_monitor
python3 latency_test.py --node gnss_heading_node
python3 latency_test.py --node gnss_checkpoint_monitor
python3 latency_test.py --node steering_aligner
python3 latency_test.py --node stanley_controller
python3 latency_test.py --node steering_aligner2
```

### Or measure everything in one run
```bash
python3 latency_test.py
```

### Output files
- **`latency_results.json`** — the actual source of truth; accumulates
  every measured node across separate invocations. Safe to inspect or
  delete (deleting it just starts the comparison over from empty).
- **`latency_comparison.xlsx`** — regenerated fresh from
  `latency_results.json` after every run; contains a Python (ms) column,
  a C++ (ms) column, a live speedup-ratio formula, and a combined-totals
  row. Open once in Excel/LibreOffice to populate cached formula values.

### Custom output filenames
```bash
python3 latency_test.py --node stanley_controller --output my_report.xlsx --results-json my_results.json
```

### If a measurement comes back `N/A`
The script prints a `[debug]` block showing the node's actual startup/log
output whenever it fails to capture messages — this is almost always
either (a) the process crashed/warned about a missing file (e.g. a CSV
path), or (b) the node genuinely has nothing to publish under the given
test conditions (e.g. a heading controller sitting inside its deadband).
Read the debug output before assuming the script itself is broken.

## Known Issues

A full write-up of logic quirks preserved from the original implementations,
their evidence, and recommended fixes is in the accompanying engineering
report (`heading_controller_pkg_report.docx`). Highlights:
- Swapped unit-conversion factors in `gps_distance_velocity_node`.
- Truthy/falsy-zero fallback bug in `gnss_checkpoint_monitor`'s CSV/YAML loader.
- `k_min > k_max` in the adaptive `steering_aligner`, inverting the intended gain curve.
- A cross-node deadlock risk between `stanley_controller` and `gnss_checkpoint_monitor` if a checkpoint is skipped without alignment completing.
